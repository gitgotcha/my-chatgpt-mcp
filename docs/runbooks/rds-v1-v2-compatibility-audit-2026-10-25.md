# RDS V1/V2 兼容性与数据清理边界

审计日期：2026-10-25  
审计基线：GitHub `main`，commit `553489dd86a9d75ed977ec23a8aea84000d05878`  
范围：仓库代码、配置、测试和既有切换记录；本说明不代表本次重新查询了生产 D1 或 Google Drive。

## 结论

RDS V2 已有独立的 `rds2_*` D1 数据路径，生产配置也将 V1 标记为退役并关闭 V1 写入；但当前仓库仍保留有限的 V1 历史读取与迁移兼容代码。因此，V1 的写入入口退役了，V1 与 V2 在代码和历史数据层面却没有完全隔离。不能仅凭“V2 可独立写入”推断旧 V1 数据可以无影响地全部删除。

本次没有删除任何云端数据。此前切换记录只证明 2026-09-08 当时清理了指定的 V1 D1 行和本机旧 Outbox，并保留了共享 Drive 父目录下的历史文件；它不是当前生产 D1 或 Drive 内容的实时盘点。

## 兼容关系

| 范围 | 当前仓库证据 | 清理影响 |
| --- | --- | --- |
| V1 API 写入 | `services/reliable-drive-sync-worker/wrangler.production.toml` 设置 `V1_WRITE_ENABLED = "false"`、`V1_RETIRED = "true"`；`src/index.js` 对 `/v1/` 返回 410，并在 retired 时跳过 V1 scheduled 工作 | 已配置的生产入口不接受 V1 写入；这不表示旧数据读取代码已移除 |
| V2 接收与后台处理 | Worker 暴露 `/v2/events`、`/v2/query`，Queue 消费由 `rds2/routes.js` 处理；生产配置仅声明 `* * * * *` V2 恢复 cron | `rds2_*` 是 V2 路径；清理旧 V1 表时必须逐表确认，禁止按名称猜测或触碰 `rds2_*`、`d1_migrations` |
| 旧事件读取回退 | `src/event-store.js` 在规范化事件目录不存在时才尝试旧目录；`src/legacy-reader.js` 只允许 `algorithm`、`interview`，且只读 | 删除对应旧目录可能使尚未迁移的历史事件不再可读 |
| 旧数据迁移 | `src/migration-store.js` 对旧注册表、事件和画像快照做扫描；dry-run 生成迁移计划，execute 只向规范目录复制缺失对象并校验哈希 | 迁移完成前删除来源会丢失迁移来源；当前实现明确不更新、移动或删除来源对象 |
| 其他旧数据 | 旧画像快照目录列在迁移路径中，但事件回退逻辑只读旧 `events` 目录 | 删除前需分别核对使用方；不能把“事件读取支持旧目录”泛化成所有旧画像都还在被 V2 查询 |

## 安全清理前置条件

只有完成以下核验后，才能制定独立的旧数据清理变更：

1. 从生产配置确认实际部署版本、V1 开关和 cron；不能用默认 `wrangler.toml` 代替生产状态证据。
2. 对明确的用户、domain 和具体旧目录做只读盘点，区分已迁移、未迁移、冲突和无法验证的对象；保存备份与清单。
3. 确认所有需要保留的旧事件已在规范目录读取，且迁移计划无未处理对象或冲突；验证当前 V2 客户端不再依赖旧目录回退。
4. 对 D1 只按 schema 与真实表用途列出精确目标；保留 V2 的 `rds2_*` 表、迁移历史及未知表。对 Drive 只针对已核实的精确对象或目录操作，禁止删除共享根目录或递归清空父目录。
5. 清理操作单独评审、备份、执行并复查结果。历史切换记录、配置文件和本地测试都不能替代生产数据核验。

如果上述任一项没有证据，就保留源数据并先做只读盘点；不要把 V1 退役等同于可以立即删除所有历史数据。
